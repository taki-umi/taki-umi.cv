プロダクト概要

海外ホテル、海外アクティビティの商材登録および予約管理をするためのシステム開発

チームの課題

  • 重複コードが複数箇所存在し、影響箇所を特定するのに時間がかかった
  • 1000行を超える巨大なクラスファイルが複数存在し、コードの見通しが悪く修正箇所の特定に時間がかかった
  • 仕様変更や機能改修に平均3~5日を要し、リファクタリング箇所でバグが発生するなど開発効率が著しく低下していた

課題に対するチャレンジ

「ソースコードの変更をしやすくする」ことを目標に、以下の段階的なアプローチで取り組みました。

1. JUnitを用いたユニットテストの充実

  • JUnitを導入し、テストケースの作成を効率化
  • 各クラスの主要なメソッドに対して、網羅率80%以上のテストコードを作成
  • ユニットテストをPR時、ブランチにマージ時にCIで実行できるように整備
  • テストケース名ルールを定めて、テストの目的を明確化
// NG - 具体的でないテスト名
@Test
public void testValidate_NG() { ... }

// OK - 具体的で分かりやすいテスト名
@Test
public void test_validate_予約番号が指定されていない場合はエラー() { ... }

2. インテグレーションテストコードの追加

  • 各APIの試験観点を洗い出し、テストケースとしてテストコードを作成
  • インテグレーションテスト用のgradleタスクを定義し、CIで実行できるように整備

結果・成果

  • デグレ発生率を大きく削減し、手戻りを大幅に減らすことができた
  • 開発者が率先してコードを変更することができるようになった
  • コード行数を平均200行以下のクラスにリファクタリングでき、可読性を向上
  • チームメンバーから「テストコードがあることで安心して変更できるようになった」との声
